# Changelog

Формат по мотивам [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/).

## [Unreleased]

### Added
- `--fix` (+ `--write`): применяет единственное известное механическое,
  доказанно безопасное исправление, которому сейчас можно доверить
  `--fix` — баг двойных скобок GAP-028 в *сгенерированном* ora2pg
  PostgreSQL-коде (`GENERATED ... AS IDENTITY ((...))` → `IDENTITY (...)`,
  почему именно этот gap подходит, а почти все остальные нет — см.
  докстринг модуля `autofix.py`). По умолчанию только печатает unified
  diff, ничего не меняет на диске; для реальной перезаписи файлов нужен
  `--write`. Самостоятельный режим, как `--verify`/`--tui`/`--explain` —
  не сочетается со сканирующими флагами.
- Английские версии `CODE_OF_CONDUCT.md`/`CONTRIBUTING.md`/`SECURITY.md`
  (теперь это канонические имена файлов, как и у `README.md`), прежний
  русский текст переехал в `*.ru.md`, у обеих версий переключатель
  языка — тот же паттерн, что у `README.md`/`README.ru.md`.
- То же самое для `ROADMAP.md`/`docs/DEVELOPMENT.md`/
  `docs/ARCHITECTURE.md`. Проверка соответствия файлового дерева
  детекторов в `scripts/doctor.py` читает `docs/ARCHITECTURE.md` по
  пути, теперь проверяет английскую версию; парсит только `.py`-имена
  файлов в дереве, а не текст комментариев, так что перевод инлайн-
  комментариев не потребовал изменений в самой проверке (проверено:
  `doctor.py` по-прежнему проходит чисто).
- Английские версии `docs/ci-integration.md`/`docs/verification-
  capability-matrix.md`, тот же паттерн, что и у остальных доков.
- В `[project.urls]` (`pyproject.toml`) добавлены `Homepage`,
  `Documentation`, `Changelog` и `Issues` — раньше там был только
  `Repository`, так что странице проекта на PyPI не хватало ссылок,
  которые она умеет отрисовывать сама.

### Changed
- Лицензия сменена с MIT на Apache-2.0 (`LICENSE`, `pyproject.toml`,
  оба README). MIT уже требовала сохранять copyright/license notice при
  распространении; Apache-2.0 дополнительно требует явно помечать
  изменённые файлы как изменённые. Единственный автор, ничьё согласие
  спрашивать не нужно.
- Новый `core.py`: `scan_source()`/`count_objects()`/`_expand_paths()`/
  `_connect_by_check()`/`_sort_findings()` (плюс `_DETECTORS`/
  `detector_names()`) переехали туда из `cli.py`. `tui_app.py` раньше
  импортировал все пять прямо из `cli.py` — интерактивный режим был
  привязан к внутренностям обычного CLI вместо общего нейтрального слоя,
  ровесника обоих. `cli.py` реэкспортирует те же имена, так что
  `main()` и внешний импорт (`from ora2pg_gap_report.cli import
  scan_source` и т. п.) не меняются.

### Fixed
- `cli.py` gains `detector_names()` — each detector's `Finding.detector`
  string derived from its function's own `__module__`, not a second,
  hand-typed list. `tests/test_terminal_report.py`'s remediation-hint
  coverage test used to hardcode its own "known detector set" instead;
  that set had drifted 9 detectors behind `cli._DETECTORS` by the time
  this was caught (GAP-029..037 were all missing from it) — it was
  silently checking only a stale subset the whole time, not real
  completeness. `scripts/doctor.py` also gains a check using the same
  function: every detector module on disk (other than `connect_by`,
  deliberately opt-in via `--check-connect-by`) must actually be
  registered in `cli._DETECTORS` — previously nothing verified this, so
  a detector fully wired into every other registry but never added to
  the scan loop itself would have shipped silently dead (registered,
  tested, documented, and never actually run).

### Performance
- `mask_strings_and_comments()`/`mask_dynamic_sql_visible()`/
  `enclosing_object_name_index()` (`plsql_lex.py`) теперь кэшируются
  (`functools.lru_cache`) — ~37 детекторов каждый вызывали
  `mask_strings_and_comments()` с одним и тем же `source` при
  сканировании одного файла (треть из них — ещё и
  `mask_dynamic_sql_visible()`/`enclosing_object_name_index()`), заново
  пересчитывая один и тот же O(n) проход по файлу по 20-70 раз. На
  `docs/research/samples/logger.pkb` (80 КБ) — `scan_source()` с
  ~0.94с до ~0.09с на холодном кэше (~10x), локальный прогон всего
  тестового набора — с ~60с до ~22с. `enclosing_object_name_index()`
  заодно возвращает `tuple`, а не `list` — при разделяемом кэшированном
  значении случайная мутация на месте в одном вызывающем коде больше не
  может незаметно испортить то, что видят остальные.

### Added
- `mypy` в CI (job `lint`, конфиг в `pyproject.toml`) с
  `disallow_untyped_defs` — не только не падает на уже аннотированном
  коде, но и реально требует аннотаций у каждой функции в
  `ora2pg_gap_report/` и `scripts/`. `oracledb` (опциональный extra
  `oracle`) размечен `ignore_missing_imports` — типы из него
  используются только под `if TYPE_CHECKING:`, пакет остаётся
  импортируемым и без него.
- `--lang`/`--set-lang`/`--tui` теперь распространяются и на текст самого
  `--help` (описание команды и help= каждого флага), и на всё
  UI-обрамление `--tui` (кнопки, статус/ошибки, заголовки таблиц) — не
  только на находки и отчёты, как раньше. `--help` разрешает язык из
  сырого argv ещё до полного парсинга (`cli.py`'s `_peek_lang_for_help()`)
  — раньше это было прямо задокументировано как нерешённое в module
  docstring `i18n.py`.

### Security
- `--format csv`: поле, начинающееся с `=`, `+`, `-`, `@`, табуляции или
  CR (снятое напрямую со сканируемого Oracle-кода — `snippet`/
  `object_name`/`source_file`), теперь экранируется ведущим `'` —
  предотвращает выполнение формулы при открытии отчёта в Excel/Sheets/
  LibreOffice (formula injection).
- `--format sarif`: `artifactLocation.uri` больше не берёт сырой
  файловый путь как есть — теперь это валидный URI-reference (RFC 3986,
  через `urllib.parse.quote`), с учётом Windows-путей (`\`, `:` буквы
  диска). Раньше документ мог быть невалидным SARIF (просто ни разу не
  пойманным существующими тестами: `jsonschema.validate()` без явного
  `FormatChecker` не проверяет ограничение `format: uri-reference`).

### Fixed
- `--tui`: любое сканируемое содержимое (имя файла, объекта, сниппет,
  сообщение), попадавшее в `Static.update()`/`DataTable.add_row()` как
  обычная строка, парсилось Textual как собственная markup-разметка —
  квадратная скобка в реальном коде или пути (`arr[i][j]`, `notes[archive]`)
  могла упасть с ошибкой разметки или исказить вывод. Весь такой текст
  теперь оборачивается в `rich.text.Text(...)`, тот же приём, что уже
  применялся в `terminal_report.py`.
- `--save`/`--baseline`, указывающие на один и тот же файл, раньше молча
  перезаписывали снапшот и сравнивали прогон сам с собой — теперь явная
  ошибка (сравнение по разрешённому пути, ловит и разное написание одного
  файла).
- `--save` больше не пишет baseline-снапшот, если сканирование было
  частичным (были ошибки чтения файлов) — такой снапшот не является
  надёжной точкой отсчёта для последующего `--baseline`.
- `--explain` проверял конфликт только с частью флагов сканирования
  (`--fail-on`, `--save`, `--baseline`, `--check-connect-by`) — теперь
  учитывает и `--verify`, `--format`, `--output`, `--severity`, `--object`,
  и текст ошибки перечисляет их все.
- `load_baseline()` требовал полный набор полей JSON Schema у каждой
  записи находки — старые снапшоты `--save`, сохранённые до появления
  `gap_number`/`failure_stage`, отклонялись. Теперь обязательны только
  реально используемые без `.get()` поля (`group_key`, `detector`).
- Несколько мест читали файл через `read_text(errors="replace")` без
  явной кодировки — на платформе с отличной от UTF-8 локалью это могло
  привести к чтению в неверной кодировке вместо честного `UTF-8` +
  replacement-символов на невалидных байтах.
- `package_state`: детектор смотрел только на объявления в `PACKAGE BODY`
  и пропускал `CONSTANT` — оба случая на практике получают тот же
  сломанный `set_config`/`current_setting`-рерайт ora2pg, что и обычная
  переменная (проверено реальным прогоном ora2pg 25.0, см.
  `docs/research/gap-036-package-state.md`). На реальном
  `logger.pkb` из тестового корпуса это было 22 непосчитанные находки.
- `recursive_with`: `WITH seed AS (...), tree AS (...)` — рекурсивный CTE,
  не первый в списке `WITH`, — не детектировался вообще, так как
  регулярное выражение требовало ключевое слово `WITH` непосредственно
  перед именем CTE.
- `bulk_collect`: проверка «это локальное объявление TYPE, а не
  `CREATE TYPE` уровня схемы» пересканировала весь префикс файла заново
  на каждое совпадение — O(n²) на файле с большим числом локальных
  `TYPE`-объявлений. Заменено на один проход вперёд с построением набора
  позиций.

## [0.7.0] - 2026-08-20

### Added
- `examples/end-to-end/` — воспроизводимый прогон всего жизненного цикла
  SCAN → миграция → VERIFY на одном реальном примере (GAP-003, `BULK
  COLLECT`/`FORALL`/локальный `TYPE`): реальный вывод `ora2pg 25.0`
  (`generated/`), вручную исправленная версия (`generated_fixed/`) — обе
  подтверждены на реальном сервере PostgreSQL 16 (создание процедуры
  проходит в обоих случаях, но `CALL` падает только у неисправленной, на
  той самой строке, что описана в исследовательском документе), `--save`
  снапшот и оба `--verify` прогона (`STILL_PRESENT` до правки,
  `NOT_DETECTED` после) сохранены как файлы, `run_demo.sh` гоняет всё
  заново и сверяет код возврата `--fail-on`. README примера отдельно
  объясняет, почему `--verify` не сворачивается в единый PASS/FAIL —
  тот же принцип, что и `NOT_VERIFIABLE`: `--fail-on`-гейт есть только
  до миграции, `--verify` — честный, перепроверяемый ответ, а не штамп.
- `docs/tui_demo.gif`/`docs/tui_demo.ru.gif` — GIF интерактивного режима
  в README рядом с обычным `docs/demo.gif`: сканирование, сравнение с
  baseline (реальные NEW/RESOLVED/UNCHANGED, посчитанные по первой и
  второй половине одного и того же реального файла-примера, не
  придуманные числа) и полное объяснение находки по клику. Рендер тем же
  способом, что и обычный demo.gif — реальный `App.run_test()` +
  `export_screenshot()` + Playwright + Pillow, EN/RU варианты как и там.
- `--tui` теперь покрывает то же самое, что и обычный флаговый workflow,
  не только сканирование и просмотр: множественный выбор путей (кнопки
  "Add to selection"/"Clear selection" — сканирует все накопленные пути
  разом, дедуп по файлу, если один и тот же файл достижим и напрямую, и
  через выбранную директорию), опциональная проверка "Check CONNECT BY"
  (то же, что `--check-connect-by`, тот же graceful warning без
  установленного ora2pg), поле для baseline-файла на экране сканирования
  (сравнение — те же NEW/RESOLVED/UNCHANGED счётчики, что и `--baseline`,
  плюс кнопка "Save baseline" на экране результатов, эквивалент
  `--save` — сохраняет полный несокращённый список находок, а не то, что
  отфильтровал severity-select, как и в CLI), и режим "Verify mode" —
  тот же пост-миграционный STILL_PRESENT/NOT_DETECTED/NOT_VERIFIABLE
  разбор по детекторам, что и `--verify`, на отдельном экране с той же
  логикой конфликтов (verify нельзя сочетать с CONNECT BY-проверкой,
  требует указанный baseline). При тестировании через Pilot нашёлся
  реальный, не связанный с новым кодом баг тест-гармнеса: клик по кнопке
  сразу после того, как `isinstance(app.screen, ...)` стал true, может
  промахнуться — Textual не гарантирует, что layout нового экрана уже
  осел к этому моменту, и клик попадает в область подсказки "^p palette"
  в футере, открывая command palette вместо нажатия кнопки; `_wait_until()`
  в tests/test_tui_app.py теперь делает один дополнительный `pause()`
  после того, как условие стало истинным, а не сразу возвращается.
- `--tui` — интерактивный экран на [`textual`](https://github.com/Textualize/textual):
  выбор файла/директории в дереве мышью или клавиатурой, severity/язык
  через выпадающие списки, сканирование по кнопке, клик по строке в
  таблице находок открывает панель с полным объяснением (сообщение,
  `GAP-NNN`, когда ломается — та же информация, что уже показывают
  `--explain` и терминальный отчёт). Опциональный extra
  (`pip install "ora2pg-gap-report[tui]"`) — `textual` не входит в
  базовую установку, обычный флаговый CLI работает как прежде и без
  него; запуск `--tui` без установленного extra даёт понятную подсказку
  по установке, а не трейсбек (проверено отдельным шагом в CI на чистом
  wheel-инсталле, без `[dev]`/`[tui]`). Самостоятельный режим, как
  `--explain`/`--verify` — не сочетается со сканирующими флагами и
  принимает не больше одного пути. Первая версия — намеренно узкий
  срез: только сканирование и просмотр, без `--save`/`--baseline`/
  `--verify`/`--check-connect-by` изнутри TUI и без множественного
  выбора путей — расширение по мере реального использования, не всё
  сразу. Оформлен темой Dracula (одна из встроенных тем `textual`) —
  севериti-цвета взяты из её же опубликованной палитры, а не из
  отдельно подобранных именованных цветов rich, чтобы не расходиться с
  общей темой; выбрана из 6 встроенных тем `textual` (Nord, Gruvbox,
  Dracula, Catppuccin Mocha, Tokyo Night, дефолтная) после визуального
  сравнения одного и того же экрана в каждой — первая версия
  использовала Nord, но по итогу сравнения выбор изменился на Dracula.
  Найдено и исправлено при реальном скриншоте, не только тестами:
  таблица находок раньше показывала полный путь в колонке File,
  вытесняя Detector/GAP за край экрана — теперь только имя файла;
  строка `GAP-NNN`/стадия в панели деталей стояла после текста
  объяснения и у длинных объяснений уезжала за пределы видимой
  области — теперь сразу под заголовком; фиксированная высота панели
  деталей не помещалась в маленьком терминале вместе с остальным
  layout — теперь пропорциональная (`fr`), а не абсолютная.

## [0.4.0] - 2026-08-16

### Added
- 7 новых детекторов, GAP-022…GAP-028. Реестр — теперь 28 подтверждённых
  gap'ов, см. `docs/research/GAP_REGISTRY.md`:
  - `cross_apply` — `CROSS APPLY`/`OUTER APPLY`, синтаксиса `APPLY` нет в
    PostgreSQL вообще.
  - `oracle_text` — домен-индекс `INDEXTYPE IS CTXSYS.*` (Oracle Text)
    отбрасывается целиком; вызовы `CONTAINS`/`CATSEARCH`/`MATCHES` не
    переносятся.
  - `recursive_with` — нативная рекурсивная `WITH ... AS (...)` (не через
    `CONNECT BY`) без обязательного в PostgreSQL ключевого слова
    `RECURSIVE`.
  - `invisible_index` — индекс `INVISIBLE` теряет своё скрытие от
    оптимизатора.
  - `read_only_table` — `CREATE TABLE ... READ ONLY` теряет гарантию
    неизменяемости; `INSERT` проходит там, где Oracle гарантированно
    блокирует его (`ORA-12081`).
  - `materialized_view_log` — `CREATE MATERIALIZED VIEW LOG` не
    конвертируется вообще, след только в DEBUG-логе.
  - `identity_column` — `GENERATED ... AS IDENTITY (...)` с опциями:
    настоящий баг двойных скобок в самой подстановке ora2pg (не пропуск
    конвертации, а поломанная конвертация — код падает при загрузке DDL).
- `docs/research/AUDIT.md` и `scripts/audit_gap_test_counts.py` обновлены
  под все 28 gap'ов.

### Fixed
- Системный баг статeмент-скоупинга: `DBMS_METADATA.GET_DDL` (этот же
  проект использует его для выгрузки DDL из Oracle) по умолчанию не
  ставит `;` в конце оператора, а часть детекторов ограничивала «свой»
  оператор как «до следующей `;`, а если её нет — до конца файла», из-за
  чего конструкция из более поздней таблицы могла ошибочно приписаться
  более ранней, незавершённой. Затронуло в том числе уже опубликованные
  `table_partitioning` и `external_table`, не только новые детекторы этого
  релиза. Добавлен общий хелпер `statement_end()` в `plsql_lex.py`,
  применён в 8 детекторах: `table_partitioning`, `external_table`,
  `invisible_column`, `global_temp_table`, `oracle_text`,
  `invisible_index`, `read_only_table`, `identity_column`.
- `invisible_index`/`read_only_table`: ложные срабатывания на столбце с
  тем же именем, что и модификатор (`invisible`/`read_only` как
  идентификатор столбца, в том числе в двойных кавычках) — теперь
  исключены.
- `invisible_index`/`read_only_table`/`oracle_text`: номер строки в
  находке теперь указывает на сам модификатор/секцию (`INVISIBLE`/`READ
  ONLY`/`INDEXTYPE IS ...`), а не на строку с открывающим `CREATE
  TABLE`/`CREATE INDEX` — важно для многострочного DDL.
- `materialized_view_log`: severity поднята с `medium` на `high` — тот же
  профиль риска, что у `table_partitioning`/`external_table` (конструкция
  молча пропадает без ошибки PostgreSQL, но означает реальную
  архитектурную потерю).

  `.sql`/`.pks`/`.pkb` файлов, не только явный список файлов.
- `docs/research/AUDIT.md` — сводная проверка доказательной базы по
  каждому из 21 gap'а (research-документ, реальный вывод ora2pg,
  expected/actual, тесты, включая guard-тесты на ложные срабатывания) и
  `scripts/audit_gap_test_counts.py`, который эти числа пересчитывает.
- `ruff` — job линтинга в CI (с явно закреплённым набором правил, не
  implicit-default — см. `[tool.ruff.lint]` в `pyproject.toml`).

### Fixed
- Атрибуция находок (`object_name` в отчёте) для реального кода, а не
  только синтетических примеров — найдено прогоном инструмента на двух
  больших открытых PL/SQL-кодовых базах (`mortenbra/alexandria-plsql-utils`,
  `oracle-samples/db-sample-schemas`, суммарно ~143k строк):
  - `PACKAGE`-спецификация (без `BODY`) и `CREATE VIEW`/`CREATE MATERIALIZED
    VIEW` теперь распознаются как контейнеры для атрибуции — раньше
    находки внутри них уходили в `UNKNOWN`.
  - `CREATE`-конструкция внутри списка привилегий `GRANT`/`REVOKE`
    (`GRANT ..., CREATE VIEW TO oe;`) больше не принимается за настоящее
    объявление объекта.
  - Строчные комментарии SQL*Plus (`REM`/`REMARK`) теперь маскируются —
    раньше реальное объявление, которому предшествовали только такие
    комментарии, могло потерять атрибуцию.
- `table_partitioning`: секционированный индекс (`CREATE INDEX ...
  GLOBAL PARTITION BY RANGE ...`) больше не приписывается случайной
  несвязанной таблице; добавлена поддержка стратегий `REFERENCE`/`SYSTEM`.
- `insert_all`: окно поиска `INTO` после `INSERT ALL`/`FIRST` расширено —
  не пропускало находку при длинном условии `WHEN`.
- `invisible_column`: `INVISIBLE UNIQUE`/`INVISIBLE PRIMARY KEY` и другие
  inline-ограничения после модификатора теперь тоже флагуются.
- `bulk_collect`: схемный `CREATE TYPE ... EDITIONABLE ... IS TABLE OF`
  больше не дублируется как находка этого детектора.
- Директории: файл, доступный одновременно напрямую и через директорию
  (`schema/ schema/logger.pkb`), больше не учитывается дважды; расширения
  файлов (`.SQL`/`.PKB`) сопоставляются без учёта регистра.

# GAP-028: `GENERATED ... AS IDENTITY (...)` with options — the double-parenthesis bug

Oracle feature: an identity column (`GENERATED ALWAYS AS IDENTITY` /
`GENERATED BY DEFAULT AS IDENTITY`, Oracle 12c+) with explicit sequence
options in parentheses (`START WITH`/`INCREMENT BY`/`MAXVALUE` and so on).

Unlike almost every other finding in this registry, this is not a missed
conversion — PostgreSQL has the feature (`IDENTITY`) and the syntax is
similar. This is a bug in ora2pg's substitution.

## Minimal example

```sql
CREATE TABLE customers (
    customer_id NUMBER GENERATED ALWAYS AS IDENTITY (START WITH 1 INCREMENT BY 1),
    name        VARCHAR2(100)
);
```

## ora2pg output (v25.0, `-t TABLE`)

```sql
CREATE TABLE customers (
	customer_id bigint GENERATED ALWAYS AS IDENTITY ((START WITH 1 INCREMENT BY 1)),
	name varchar(100)
) ;
```

The options clause is wrapped in **an extra pair of parentheses** —
`IDENTITY ((START WITH 1 INCREMENT BY 1))` instead of the correct
`IDENTITY (START WITH 1 INCREMENT BY 1)`.

## Observed problem

Confirmed against a real PostgreSQL 16 — it fails while loading the
`CREATE TABLE` itself, before any function is called (the earliest
manifestation in the whole registry, the same class as GAP-021):

```
ERROR:  syntax error at or near "("
LINE 2:  customer_id bigint GENERATED ALWAYS AS IDENTITY ((START WIT...
```

Checked separately:
- `GENERATED ALWAYS AS IDENTITY` **without** explicit options converts
  correctly — the bug is specific to the case with options in parentheses.
- `GENERATED BY DEFAULT AS IDENTITY (...)` with options behaves
  identically — the same double-parenthesis bug.

**Reproducible: YES.** Ora2Pg version: 25.0.

## Verdict

**Gap confirmed.** Implemented in
`ora2pg_gap_report/detectors/identity_column.py`. Given that `GENERATED
... AS IDENTITY` is the modern (12c+) and increasingly common way to
declare an auto-increment column in Oracle, this bug may be encountered
more often than most of the more exotic findings in this registry.

# GAP-013: `PARTITION BY RANGE/LIST/HASH/REFERENCE/SYSTEM` — секционирование таблиц полностью отбрасывается

Oracle feature: декларативное секционирование таблицы
(`PARTITION BY RANGE/LIST/HASH/REFERENCE/SYSTEM (...)`) — архитектурная
стратегия хранения и обслуживания больших таблиц (partition pruning,
раздельное обслуживание секций). Проверено на всех пяти стратегиях —
поведение ora2pg одинаковое для каждой.

## Минимальный пример

```sql
CREATE TABLE sales (
    sale_date DATE,
    amount    NUMBER
)
PARTITION BY RANGE (sale_date) (
    PARTITION p1 VALUES LESS THAN (DATE '2020-01-01'),
    PARTITION p2 VALUES LESS THAN (MAXVALUE)
);
```

## Вывод ora2pg (v25.0, `-t TABLE`, и отдельно `--estimate_cost -t TABLE`)

```sql
CREATE TABLE sales (
    sale_date date,
    amount    numeric
);
```

`PARTITION BY` и все секции (`p1`, `p2`) полностью исчезают из вывода —
таблица создаётся как обычная, несекционированная. Ни ошибки, ни
предупреждения — включая `--estimate_cost`, который тоже не отмечает эту
таблицу никаким образом.

## Наблюдаемая проблема

Подтверждено на реальном PostgreSQL 16: сгенерированный `CREATE TABLE`
выполняется без единой ошибки — валидная, просто другая таблица.

Для небольших таблиц это может быть безобидно, но для тех, ради которых
секционирование вообще применялось (крупные таблицы с задачей
partition pruning или раздельного обслуживания секций), это тихая потеря
архитектурного решения — без единого сигнала об этом нигде в выводе
ora2pg. PostgreSQL поддерживает декларативное партиционирование, но с
другим синтаксисом (`CREATE TABLE ... PARTITION OF ... FOR VALUES ...`) —
секции нужно пересоздавать вручную.

Отдельно проверено на коллизионные случаи, чтобы не путать эту
конструкцию с похожим синтаксисом:
- **Partitioned outer join** (`table_alias PARTITION BY (col) RIGHT OUTER
  JOIN ...`) — не флагуется, там нет `RANGE`/`LIST`/`HASH`.
- **Оконная функция** (`SUM(...) OVER (PARTITION BY col ...)`) — не
  флагуется, там тоже нет `RANGE`/`LIST`/`HASH` сразу после
  `PARTITION BY`.
- **Секционированный индекс** (`CREATE INDEX ... GLOBAL PARTITION BY
  RANGE (col) (...)`) — валидный, но отдельный от секционирования таблицы
  синтаксис Oracle. Поиск `PARTITION BY` ведётся строго в пределах текста
  конкретного `CREATE TABLE` (до его завершающей `;`), а не по принципу
  «ближайшая предшествующая по файлу таблица» — иначе секционированный
  индекс мог бы быть ошибочно приписан случайной несвязанной таблице
  раньше по файлу (найдено на код-ревью, исправлено до мержа).

**Reproducible: YES.** Ora2Pg version: 25.0.

## Вердикт

**Gap подтверждён.** Реализовано:
`ora2pg_gap_report/detectors/table_partitioning.py`. Требует
`PARTITION BY (RANGE|LIST|HASH)\s*\(` — именно наличие открывающей скобки
сразу после ключевого слова отличает настоящее секционирование таблицы от
partitioned outer join и оконных функций.

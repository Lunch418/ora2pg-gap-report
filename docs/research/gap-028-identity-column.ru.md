# GAP-028: `GENERATED ... AS IDENTITY (...)` с опциями — баг двойных скобок

Oracle feature: столбец-идентификатор (`GENERATED ALWAYS AS IDENTITY` /
`GENERATED BY DEFAULT AS IDENTITY`, Oracle 12c+) с явными опциями
последовательности в скобках (`START WITH`/`INCREMENT BY`/`MAXVALUE` и
т.д.).

В отличие от почти всех остальных находок в этом реестре, это не
пропуск конвертации — сама фича (`IDENTITY`) у PostgreSQL есть и
синтаксически похожа. Это баг именно в подстановке ora2pg.

## Минимальный пример

```sql
CREATE TABLE customers (
    customer_id NUMBER GENERATED ALWAYS AS IDENTITY (START WITH 1 INCREMENT BY 1),
    name        VARCHAR2(100)
);
```

## Вывод ora2pg (v25.0, `-t TABLE`)

```sql
CREATE TABLE customers (
	customer_id bigint GENERATED ALWAYS AS IDENTITY ((START WITH 1 INCREMENT BY 1)),
	name varchar(100)
) ;
```

Секция опций обёрнута в **лишнюю дополнительную пару скобок** —
`IDENTITY ((START WITH 1 INCREMENT BY 1))` вместо корректного
`IDENTITY (START WITH 1 INCREMENT BY 1)`.

## Наблюдаемая проблема

Подтверждено на реальном PostgreSQL 16 — падает уже при загрузке самого
`CREATE TABLE`, ещё до вызова любой функции (самое раннее по времени
проявление из всего реестра, тот же класс, что и GAP-021):

```
ERROR:  syntax error at or near "("
LINE 2:  customer_id bigint GENERATED ALWAYS AS IDENTITY ((START WIT...
```

Отдельно проверено:
- `GENERATED ALWAYS AS IDENTITY` **без** явных опций конвертируется
  корректно — баг специфичен именно для случая с опциями в скобках.
- `GENERATED BY DEFAULT AS IDENTITY (...)` с опциями ведёт себя
  идентично — тот же баг двойных скобок.

**Reproducible: YES.** Ora2Pg version: 25.0.

## Вердикт

**Gap подтверждён.** Реализовано:
`ora2pg_gap_report/detectors/identity_column.py`. Учитывая, что
`GENERATED ... AS IDENTITY` — современный (12c+) и всё более
распространённый способ объявить auto-increment столбец в Oracle, этот
баг может встречаться чаще, чем большинство более экзотических находок
в этом реестре.

# GAP-015: `CREATE CONTEXT` — application context не конвертируется вообще

Oracle feature: `CREATE CONTEXT` — объявление application context, часто
основа VPD/row-level security через `SYS_CONTEXT` в связке с
`DBMS_SESSION.SET_CONTEXT`.

## Минимальный пример

```sql
CREATE CONTEXT hr_ctx USING hr.set_ctx_pkg;
```

## Вывод ora2pg (v25.0, `-t TABLE` / полный экспорт схемы)

Конструкция полностью пропадает из вывода — ни ошибки, ни
предупреждения на уровне обычного лога. Единственный след — служебная
строка уровня **DEBUG** ("unhandled line"), которую легко пропустить при
реальной миграции (обычный лог-уровень её не покажет).

## Наблюдаемая проблема

У PostgreSQL нет прямого аналога application context. То, что
использовало этот контекст в Oracle (обычно `SYS_CONTEXT('hr_ctx', ...)`
в политиках VPD или в условиях запросов), при переносе просто теряет
источник данных — без единого сигнала о том, что часть конфигурации
безопасности вообще не была перенесена. Для сценария VPD это
потенциально серьёзная тихая брешь: политика может либо не сработать
вообще, либо сработать на пустых/дефолтных значениях.

Ближайшие пути ручной миграции — `current_setting()`/`set_config()` для
сессионных переменных общего назначения, либо Row-Level Security
(`CREATE POLICY`) для непосредственно сценария VPD.

**Reproducible: YES.** Ora2Pg version: 25.0.
